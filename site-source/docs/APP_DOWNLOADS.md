# Android и Windows: выдача установщиков

Исходная ветка действующего сайта: `codex/vpn-first-site`, каталог `site-source/`. Корневая ветка `main` содержит другой статический сайт для `vpn.freerus.site`.

Компонент `components/VpnDownloads.tsx` включён в `/` и `/epic-vpn`. Ссылки и размеры задаются в `data/downloads.ts`. Установщики размещаются в GitHub Releases, не в git и не в публичных ресурсах сборки. Кнопки являются обычными ссылками, работают без JavaScript; HTTP attachment отдаёт GitHub.

Релиз `apps-2026-09-28`:
- `FREE-RUS-VPN.apk`: 89 440 770 байт, источник `FREE-RUS-VPN (1).apk` владельца проекта.
- `FREE-RUS-VPN-Setup.exe`: 108 819 033 байта, источник `FREE-RUS-VPN-Setup (1).exe` владельца проекта.

Не подменять их старыми debug APK. Не утверждать, что установка или VPN проверены, на основании успешного скачивания.

## Проверка перед выкладкой

1. Опубликовать релиз с обоими файлами; черновые релизы недоступны анонимным посетителям.
2. Выполнить полный GET каждой ссылки, проверить итоговый HTTP 200, размер, attachment и совпадение скачанного файла с оригиналом. HEAD недостаточно.
3. Проверить главную и `/epic-vpn` на мобильной и настольной ширине, отсутствие горизонтального скролла и наличие двух ссылок на установщики.
4. Выполнить `npm run build` и `npm run lint`. В исходной ветке `tests/rendered-html.test.mjs` содержит устаревшие проверки медиа-главной и пилотного VPN; учитывать отдельно от новых ошибок.
5. Деплой приложения на VPS выполняется по `docs/DEPLOYMENT_CHAIN.md`; GitHub Pages в корне репозитория не публикует приложение из этого каталога на freerus.site.

Для локальной сборки нужен игнорируемый `.openai/hosting.json`: например `{"d1":"DB","r2":null}` для локальных привязок. Это не production-конфигурация. Production ID и секреты в git не добавлять.

Для нового релиза использовать новый тег и обновить ссылки и размеры одновременно. При недоступности GitHub пользователю показана инструкция и контакт проекта.
